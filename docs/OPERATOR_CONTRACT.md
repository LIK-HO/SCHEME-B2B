# Operator contract: SCHEME-B2B

Дата: 2026-09-19

## Цель интерфейса

Оператор должен уметь за один короткий цикл:

**задать поиск → запустить/включить автоматизацию → увидеть новые пригодные компании → понять, почему они попали в выборку → принять/отклонить → работать с потребностью и контактом → получить итог.**

Всё остальное вторично.

## 1. Главный экран

На первом экране достаточно пяти блоков:

1. **Поиск** — география, сфера, объём.
2. **Состояние** — активен/выключен, последний и следующий запуск.
3. **Новые** — только непросмотренные пригодные результаты.
4. **Работа** — принятые клиенты и их потребность.
5. **Состояние системы** — только понятный сигнал «работает / есть ошибка / требуется действие».

## 2. Карточка новой компании

Оператору видны только данные, необходимые для решения:

- Компания;
- ИНН;
- ОГРН/ОГРНИП;
- Город;
- Сфера;
- Потребность/сигнал;
- Телефон;
- Почта;
- Сайт;
- Источник;
- Приоритет;
- состояние проверки ФНС;
- комментарий/резюме.

Технические поля P0/P1, run_id, lease и служебные идентификаторы не выводятся в основной рабочий поток.

## 3. Действия оператора

Минимальный набор:

- принять;
- отклонить;
- открыть источник;
- открыть контакт;
- изменить потребность/резюме;
- включить/выключить автопоиск;
- выбрать частоту 1/2/3 раза в день;
- запустить поиск вручную;
- включить/выключить Email и MAX уведомления.

## 4. Автоматизация

Оператор не управляет внутренней логикой дедупликации, retry, lease или FNS freshness.

Он управляет только политикой работы:

**когда искать, где искать, сколько искать и куда сообщить результат.**

## 5. Результат запуска

Уведомление содержит:

- время запуска;
- сколько кандидатов обработано;
- сколько новых компаний найдено;
- сколько дубликатов подавлено;
- сколько отклонено;
- сколько ошибок;
- достигнуты ли лимиты;
- нужна ли помощь оператора.

Никаких длинных технических трасс и внутренней диагностики в обычном уведомлении.

## 6. Принцип простоты

Если элемент интерфейса не помогает найти, проверить, понять потребность или обработать клиента — он не относится к основному операторскому экрану.

Если техническое поле необходимо для надёжности, оно остаётся в core/audit, но скрывается из ежедневной работы.
